# Server batch 1 (Tier B/C) — Gate 1 across n, the fall rule outside its fit, and the first `d_solv` measurements

Draft PR body for `claude/server-batch-1` → `main`.  Numbers are regenerated by
`python3 server/jobs/summarise_batch1.py`; the full write-up is
[`results/REPORT_server_batch1.md`](../REPORT_server_batch1.md).

## What this does

Tier-A batch 1 could not decide Gate 1 (every full-system D=4 run in pure Python saturates), could
not test the calibrated fall-count rule outside n ≤ 16, and had no measurement of the F4 solving
degree.  This batch builds the Tier-B/C toolchain, adds an M4RI rank backend behind
`--backend sage`, and runs all three.

## Work beyond the prompt

Seven of the runs in this branch were not asked for by the batch prompt.  They are documented, with
cost and justification, in [`results/server/EXTRA_EXPERIMENTS.md`](EXTRA_EXPERIMENTS.md) — please
read that before merging.  In short, three of them corrected conclusions this branch had already
written down (the ℓ = 3 "cross-S-box mechanism", the 16 "genuine" quartic relations, and a
block-order comparison Magma never performed), and four were needed to reach thresholds the prompt
itself sets (four values of n for Gate 1, a usable D = 5 control, one completed E05 size, and every
admissible e at n = 19, 20).  §10 of that file lists the additional compute that produced nothing.

## Needs a human decision

1. **Is the ℓ = 3, n = 11 row worth chasing?**  For most of this batch it looked like a shape
   effect — the excess localises onto the three first-layer S-boxes, exactly what AIM3-V has and
   AIM3-I/III does not — and §2 was written that way until n = 13 came back with exactly 0.  The
   report now reads it as a small-parameter effect and says so, while listing the control that
   would settle it (four S-boxes on *disjoint* variables; the random control cannot serve, having
   no falls to add up).  Worth a follow-up, or closed?
2. **Is the 0.9 saturation threshold strict enough?**  ℓ = 3 at n = 11 sits at 0.52, well inside
   the admissible band, and still produced a number that does not survive one step in n.
3. **`d_solv` = that of a random system of the same shape.**  This is a negative result for the
   "structure buys a lower solving degree" hypothesis, and it belongs in the paper as such.  It is
   *not* an extrapolation to the real parameters and the report refuses to make one.
4. **E10 as written in the ROADMAP is not executable.**  A block-order F4 step-degree comparison
   needs Sage/PolyBoRi (or a positive-dimensional instance); Magma 2.24 computes grevlex and
   converts.  Should E10 be re-scoped or dropped?
5. **`paper/claims_ledger.md`** — §9 of the report lists the rows this batch would add or change.
   Nothing was applied.
