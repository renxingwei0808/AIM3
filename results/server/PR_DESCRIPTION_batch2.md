## What the batch was asked, and what it answers

**Q1 — what is the calibrated solving-degree law?**  `d_solv` is 4–5 across every completed cell
(ℓ = 1, n = 11..17; ℓ = 2, n = 9..15), so no law is fitted: four completed sizes of a quantity that
takes two values do not determine a growth rate.  What is new is the **hybrid-guessing staircase**.
With k bits of pt fixed to their true values, `S_quad` and a random system of identical shape follow
the same staircase in k, except that the structured one takes one of its steps **two guessed bits
earlier** — at n = 15 the 5 → 4 step is at k = 2 against the control's k = 4; at n = 13 `S_quad`
takes a further 4 → 3 step at k = 6 that the control does not take.  Two seeds, two tools, every cell
complete.  **This is the batch's one structural gain and its main open question.**

The Hilbert side check quantifies the ROADMAP's C3/C4 objection: at ℓ = 2, n = 11, D = 5 the
`S_quad` Macaulay matrix has **13555 more syzygies** than the Boolean semi-regular model predicts,
while the random control of the same shape lands one short of full column rank.  The departure at
D = 3 is 264.

**Q2 — is there content in the S-box ideal above the quadratic ideal?**  Yes for generic exponents:
at n = 16, D = 5 leaves **10n quartics of `I(V_e)` unreached**, and **0** for the {−3} class — the
reverse of the degree-3 asymmetry.  Batch 1's reading of `falls_D5` is **refuted**: the products of
the new cubics with the variables carry exactly **18n linear relations** (both sizes, both classes,
even though the product counts differ), so `falls_D5 = (#cubics)·2n − 18n + net` with net = 25n
generic / 10n {−3}.  And the generic closed form `n(4n+7)` itself **fails at n = 18** — 64n measured
against 79n predicted, decreasing in n, which no `4n + c` allows.  Two more n = 18 exponents are
running to decide between "the form is a fit that stops at n = 16" and "n = 18 hides a degenerate
class the classifier misses".

**Q3 — can the kernel model be attacked non-Boolean?**  Three negative results.  Block-restricted XL
does not linearise earlier (n = 7, D = 5: corank still 909378).  The first-layer rank defect is
structurally real — corank exactly 1 at the true W at every n — but a random W drops rank only
1.4–2.2× more often than a uniform matrix of the same shape, so the condition carries ≈ n−1 bits and
prunes the W space to ≈ 2^{n+1}, the same order as the pt search it was meant to replace.  Block
orders remain **unmeasurable**: batch 1 was blocked by Magma computing in grevlex whatever order is
declared, batch 2 by PolyBoRi aborting (SIGABRT) on exactly the pt-first orders of interest — 18 of
43 runs completed, and the ones that did say the t-first order is *worse* (14–17 against grevlex 5).

**T4 (task 4, unblocked by PR #5).**  Sage's `OrePolynomialRing` reproduces the Tier-A measurement on
the same instances — **28 comparisons, 0 disagreements** — and the ring-level picture extends to
**n = 24**.  The decisive number: with t₁ true and t₀ ranging over all of F_{2ⁿ}, **every** coefficient
of the monic lclm has univariate degree **2ⁿ − 1** and ANF degree **n**, the maxima, at n = 8..19 and
in two independent implementations.  So eliminating pt is exact and cheap, and what it leaves is
dense: any degree-sensitive finish costs Ω(2ⁿ), the same order as guessing pt.

**E05 (task 5).**  Eq1 is separable, so t₁ is eliminated by tabulating V and looking W up.
**18 completed sizes, n = 7..24, no censoring**, slope of log2(seconds) = 1.167 with every successive
ratio in 1.71..3.00.  Batch 1's `Resultant` needs 294.5 s at n = 7 and does not return at n = 8 —
a 49000× gap at the one size both reach.  T3's reduced system is solvable in Θ(2ⁿ): the same order as
B3, which is T3.2's expected negative result, now measured rather than inferred from a degree.

## Four measurement defects found and fixed

All four are the same failure mode — **a run that did not finish, or did not finish the way it looks,
being recorded as a value** — and all four are documented in the report §6 rather than quietly fixed:

1. `run_polybori.py` derived `censored` from the timeout alone and counted **SIGABRT crashes as
   completed runs**.  Before the fix the table appeared to show block orders cutting `d_solv` from 5
   to 2; that reading is withdrawn.
2. `t4_lclm_degrees.py` wrote a censored row with a different set of columns, so `record()` refused
   it and the escalation died at its first timeout.
3. The E05 timing curve had a **29× step at n = 17** — `src/aim3/gf2n.py` drops its log tables above
   n = 16.  Fitting a slope across it would have produced a fabricated exponent; `--tables` removes
   it and extends the range to n = 24.
4. Sage preparses `^` as **exponentiation**, so a Möbius transform written `arr[i] ^= arr[i^s]` was
   computing a tower of powers.  It raised `MemoryError` — the lucky case; the same rewrite on
   `s ^= f0` returns a wrong number in silence.  Now in `server/ENVIRONMENT.md`.

A claim this report made and then withdrew: that Sage's `OrePolynomialRing` is 50–1000× slower per
`lclm` than `src/aim3/ore.py`.  That was defect 4 measuring itself; Sage is in fact the faster of the
two (1684 s against 9515 s for the 2¹⁸-point sweep).
